# ОРБИТА — пространственная аналитика департамента

Текущий визуал: космическое пространство с Землёй и звёздами в светлой/тёмной теме, матовые стеклянные карточки с blur. Сетка 3×3 и все 10 фокусов сохранены. Статус проверки/публикации — [HANDOFF](docs/HANDOFF.md). [14 новых скриншотов ZIP](docs/downloads/orbita-space-2026-10-18.zip).

Актуальный hotfix: обзор 3×3 с одним месячным слотом (количество/объём/«Разом»); все 10 дашбордов доступны в фокусе. XR показывает три стенда одновременно, график и точные значения — на одной панели. [Новые скриншоты ZIP](docs/downloads/orbita-hotfix-2026-10-18.zip) · [Сверка полного аудита](docs/evidence/hotfix-2026-10-18/audit-crosscheck.md).

Предыдущий этап Quest 3S от 18 октября: светлая/тёмная темы, 10 карточек в обзоре, фронтальные XR-группы, отдельные шкалы плана и риска, пространственные страницы точных значений и перецентровка. [Актуальная передача](docs/HANDOFF.md) · [Аппаратная приёмка](docs/QUEST_ACCEPTANCE.md) · [Снимки предыдущего этапа](docs/downloads/orbita-quest-update-2026-10-18.zip).

Интерфейс поддерживает UA/EN/RU: украинский по умолчанию, язык сохраняется отдельно от данных. Переключатель находится в шапке и настройках. Актуальная пространственная доработка, перевод и проверки описаны в docs/HANDOFF.md и docs/WORKLOG.md; исходное задание — docs/source/spatial-localization-request-2026-10-17.md.

React + TypeScript приложение по предоставленному ТЗ для браузера и Meta Quest 3S. Десять дашбордов объединены в три блока: платежи, кассы, АТМ/ТСО/Recycle. По умолчанию используется исходный демонстрационный срез, поэтому сервер и ключи для первого запуска не нужны.

Передача другим агентам: **[полное описание проекта и порядок продолжения](docs/HANDOFF.md)**. Правила работы — [AGENTS.md](AGENTS.md); история и доказательства — [WORKLOG](docs/WORKLOG.md) и [VERIFICATION](docs/VERIFICATION.md).

## Текущий визуал

Матовые поверхности без декоративных номеров, рамок и штрихов; заголовки в обычном регистре. Убраны вводные абзацы, повторные подписи и очевидные подсказки; остались данные, действия и значимые состояния. [Обзор](docs/evidence/desktop-copy-cleanup.png) · [Телефон](docs/evidence/mobile-copy-cleanup.png).

В «Открыть в пространстве» доступен настоящий процедурный 3D-кабинет с окнами, мебелью и растениями: [день](docs/evidence/procedural-room-day.png) · [вечер](docs/evidence/procedural-room-night.png) · [панорама](docs/evidence/spatial-copy-cleanup.png). «Осмотреть комнату» временно скрывает аналитику и позволяет оглядеться; «Вернуть аналитику» возвращает панораму. В VR используется та же комната, в AR — passthrough. Только обычный 2D-обзор сохраняет локальное фоновое изображение Image Gen.

## Быстрый запуск

Требуется Node.js **22.12+** (проверено 24.19.0) и npm. Из каталога репозитория:

```sh
npm ci
npm run dev
```

В подготовленной cloud-среде каталог проекта — `/workspace/-`. Если домашний npm-cache недоступен, используйте `export npm_config_cache=/workspace/.npm` перед командами. Vite использует порт 5173; локальный адрес выводится в терминале. Это адрес для внутренней проверки, а не опубликованное приложение.

```sh
npm run typecheck
npm run test
npm run build
npm run preview
```

`npm run build` создаёт `dist/` с PWA, локальными шрифтами и профилями контроллеров. `npm run preview` обслуживает сборку на порту 4173. Процессы нужно запускать заново в новой машине, установленные зависимости и файлы сохраняются снимком среды.

## Что работает

- Панорама из трёх блоков и отдельный просмотр платежей, касс или оборудования.
- Д1: январь/отчётный месяц по каналам + доля ДБО; Д2/Д3: количество/объём, план и спарклайны; переключатель «Вместе» показывает оба.
- Д4/Д6: годовые показатели. Д5: структура кассовых операций. Д7: работающие кассы, вакансии и простой. Д8/Д9: операции и объём устройств. Д10: три временных ряда оборудования и простой.
- «В фокус» открывает каждую из 10 карточек с крупной диаграммой и таблицей точных значений. Escape возвращает фокус.
- Окружения «Кабинет» и тёмное; сокращённые/точные числа; адаптация для узкого экрана; локальные кириллические шрифты.
- Настройки API (`?admin=1`), проверка соединения и полной схемы, Hybrid/Strict, последовательный опрос 0/5/15/30/60с, таймаут 4с.
- Три демосценария, быстрый редактор показателей, полный JSON, копирование/скачивание, симуляция и синхронизация вкладок одного браузера/origin.
- Настоящая WebGL-сцена и вход в WebXR AR/VR при поддержке браузером. Встроенная эмуляция устройства отключена, поэтому отсутствие шлема не маскируется.

## Работа с API

В «Источники данных» задайте адрес и при необходимости Bearer token. Нажмите «Проверить соединение», затем «Сохранить подключение».

- **Демоданные:** локальный mock, без сетевых запросов к API.
- **API с резервным снимком:** при сбое показывает последний валидный live-снимок в памяти либо демоданные, с явным статусом источника.
- **Только API:** ошибка отображается честно; демоданные не подменяют live-ответ. Предыдущий live-снимок сохраняется в текущем сеансе с пометкой ошибки.

API выполняет только GET. Контракт и ограничения: [docs/API_CONTRACT.md](docs/API_CONTRACT.md). API URL должен быть HTTPS (HTTP допускается для localhost-разработки) или относительным путём. Не передавайте секреты в query string. Токен хранится только в памяти вкладки, не синхронизируется и исчезает после перезагрузки. Данные live API не пишутся в localStorage или PWA-cache.

Внешний сервер должен разрешить CORS для origin приложения и заголовка Authorization. Опциональный **dev-only** proxy:

```sh
API_PROXY_TARGET=https://your-approved-api.example npm run dev
```

В интерфейсе выберите `/api/dashboard`; префикс `/api` сохраняется. Proxy не отключает TLS-проверку. В production нужен ваш reverse proxy либо настроенный CORS. Админка настройки не является серверной системой ролей; доступ контролирует ваш API.

Настройки на ноутбуке не переносятся автоматически в отдельный шлем: localStorage/BroadcastChannel работают внутри одного origin и браузерного профиля. Для защищённой настройки шлема с другого устройства понадобится согласованный серверный механизм, которого в исходном архиве нет.

## Meta Quest 3S / HTTPS

WebXR требует secure context. Для локальной разработки есть:

```sh
npm run dev:https
```

Плагин создаёт локальный самоподписанный сертификат. Этот режим проверяет HTTPS-разработку, но **не создаёт доверенный сертификат для шлема**. Для использования Quest настройте доверенный устройством сертификат через вашу инфраструктуру или разверните `dist/` на доверенном HTTPS-хосте. Не отключайте проверку сертификатов и не передавайте рабочий токен на непроверенный сервер.

1. Откройте HTTPS-приложение в Meta Quest Browser.
2. Выберите «Открыть в пространстве».
3. Выберите AR для passthrough или VR для тёмного окружения.
4. Наведите луч контроллера и нажмите курок, либо используйте луч руки и pinch.
5. Выберите карточку: она появится перед текущим взглядом на расстоянии 1,1м. Повторное нажатие или «Вернуть панель» отменяет фокус.
6. «Завершить XR-сеанс» возвращает браузерный режим.

WebGL использует CanvasTexture и один адаптер данных с DOM-дашбордами. Обычный HTML overlay не является XR-панелью. Контроллерные JSON-профили поставляются локально; внешние модели рук/контроллеров не нужны, отображается луч взаимодействия. Полный data entry выполняется в браузерной панели настроек.

Для проверки без шлема доступен WebGL-просмотр и управление поворотом. Можно отдельно установить Immersive Web Emulator в вашем Chrome; его результаты не заменяют тестирование линз, hand tracking, passthrough и производительности на реальном Quest 3S. Нативный APK не собирается этим проектом.

## PWA / автономная работа

Production-сборка содержит manifest, иконки и service worker. После первого успешного открытия кешируется оболочка, demo JSON, шрифты и используемый пространственный код. Неиспользуемые комнаты встроенного эмулятора исключены из precache. В offline работает демонстрационный режим; API остаётся сетевым источником и следует выбранной fallback-политике.

Новая сборка предлагает «Обновить приложение» и применяется явно в текущей вкладке. Если старая установленная версия всё ещё показывает «Всё в поле зрения.», откройте [обновление Орбиты](https://ddintsen.github.io/-/?orbita-update=1). Демоданные и несекретные настройки сохранятся. Проверка перехода с настоящей старой PWA: `npm run test:update` после сборки с `VITE_BASE_PATH=/-/`; нужны Chromium и история Git (в shallow clone сначала получите commit552750e). Подробности — [доставка](docs/DEPLOYMENT.md).

Установка PWA зависит от возможностей текущей версии Meta Quest Browser; manifest сам по себе не гарантирует появление кнопки установки. Публикация и установка на реальном устройстве в этой cloud-сессии не выполнялись.

## Проверки и документация

```sh
npm run test              # бизнес-логика, schema, API errors/timeout/cancel
npm run test:e2e          # Chromium: пользовательские действия + axe
npm run test:production   # после запуска preview: production/PWA/offline/WebGL
npm run tokens:check     # DESIGN.md и сгенерированные адаптеры
npm run format:check
```

E2E использует системный `/usr/bin/chromium`. На другой машине задайте `CHROMIUM_PATH=/path/to/chromium`; tests открывают только локальный Vite. См. [docs/VERIFICATION.md](docs/VERIFICATION.md) для фактических результатов и ограничений.

- [CONTEXT.md](CONTEXT.md) — запрос пользователя, референсы и точка входа для продолжения.
