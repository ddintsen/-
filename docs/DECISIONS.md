# Решения и расхождения

## 2026-10-16 — первая реализация
1. **Два способа отображения одних данных.** Доступный DOM/SVG-интерфейс в браузере; настоящие WebGL mesh + CanvasTexture в immersive WebXR через React Three Fiber и @react-three/xr v6. `<Html transform>` из Drei не рендерится в XR framebuffer; обещание обратного в исходном ТЗ технически неверно. DOM overlay не заменяет пространственные панели.
2. **Исходные данные сохраняются.** Октябрь 2026 и годовой план 5–8% не согласуются с пояснением ТЗ о февральском срезе. Не исправляем цифры выдумкой. Это демонстрационный срез; зелёная дуга показывает выполнение, но не утверждает соответствие календарному темпу. В интерфейсе нет ложного текста «годовой план в норме».
3. **Данные не аддитивны.** Сумма каналов Д1 не совпадает с общим количеством Д2; Д2 и Д3 в оригинальном JSON имеют одинаковые абсолютные значения. Не вычисляем агрегат из другого дашборда. Каждый виджет использует свой контракт; уточнение боевых данных потребуется у владельца API.
4. **Порог простоя.** ТЗ имеет приоритет над прототипом: >6,5% — красный. Прототип ошибочно откладывает красный до >10%. Интервал (2;6,5] — предупреждение, <=2 — зелёный. Прогресс плана всегда отдельная шкала. Длина дуги строго пропорциональна значению, без искусственного раздувания 6% до 22%.
5. **Без сохранения токена.** Bearer token только в памяти текущей вкладки. Не сохраняем в localStorage, BroadcastChannel, URL, JSON или логах. Сохраняемые настройки не содержат секретов. Демоданные синхронизируются между вкладками; боевые данные не пишутся на диск браузера.
6. **Операции API — только чтение.** Авторизация/роли остаются у API; панель подключения не является системой административных прав. Hybrid показывает последний валидный снимок с явным статусом; Strict Live не маскирует ошибку демоданными.
7. **Стек.** React/TS/Vite, Zustand, Zod, Three/R3F/XR. Общие SVG-графики вместо ECharts: конечный набор 10 диаграмм, меньше зависимостей, семантические описания, точные шкалы. Отдельная Canvas-отрисовка использует тот же адаптер данных для шлема. CSS tokens, без runtime Tailwind CDN.
8. **XR-позиции.** Исходное ТЗ противоречит само себе: боковые координаты ±1,55/−1,45 м дают дистанцию 2,12 м, а не 1,8 м. Берём конкретные координаты ТЗ, центр 1,8 м, yaw ±28°. При фокусе карточка перед пользователем на 1,1 м. Финальная эргономика и оптика проверяются на Quest 3S.
9. **Локализация.** Русский UI, шрифты с кириллицей; числа ru-RU, валюта из JSON, служебные временные метки Europe/Kyiv. Украинский UI не обещается, кириллические данные поддерживаются.
10. **Границы поставки.** Создаётся рабочее браузерное/WebXR/PWA-приложение. Нативный APK в ТЗ альтернативный путь, не входит в эту веб-сборку. Нет реального API, шлема или разрешения на публикацию; эти проверки не могут быть заявлены выполненными.
11. **Дистанционный XR-обзор.** В панораме шлема используются укрупнённые краткие показатели; по выбору открывается полная диаграмма с деталями на 1,1м. Рисовать весь desktop-текст на маленькой текстуре на расстоянии означало бы повторить проблему мелких подписей прототипа. Браузерный 3D-preview также имеет клавиатурный select для всех 10 карточек.
12. **Шрифты и профили офлайн.** Inter/Manrope и controller profile JSON поставляются с приложением; модели рук/контроллеров не загружаются извне. Наведение рисуется лучом. Полная 3D-анатомическая модель руки не заявляется.
13. **Между вкладками ≠ между устройствами.** localStorage/BroadcastChannel синхронизируют один origin в одном браузерном профиле. Предложенная в ТЗ настройка шлема с ноутбука не возникает из них автоматически. Без отдельного сервера безопасной передачи настроек/аутентификации это не реализовано; токен не передаётся через URL, QR или локальный JSON как обходной путь.

## 2026-10-17 — доставка обновлений в уже установленную PWA
- Пользователь подтвердил: старый интерфейс виден именно на ddintsen.github.io/-/. Fresh-browser CI уже проверял минимальный интерфейс, но не переход с установленной старой версии. У prompt-worker была регистрация без UI применения, поэтому новая сборка могла ждать бесконечно. Query cache busting сам по себе не обходил старый NavigationRoute.
- Сохраняем prompt, а не глобальную автоматическую перезагрузку. AppUpdate владеет регистрацией (injectRegister=false), проверкой обновлений и явным SKIP_WAITING. controllerchange перезагружает только вкладку, нажавшую кнопку; прочие показывают предложение. Dev/standalone исключены. clientsClaim переключает управление после активации.
- public/sw-recovery.js импортируется worker. Отсутствие отдельного scope-specific cache marker означает старый протокол: один раз skipWaiting без перезагрузки обычных вкладок; при активации создаётся marker. Это снимает тупик, даже если пользователь заходил после deploy до специальной ссылки. Следующие сборки ждут кнопку. Точный app-root URL с orbita-update=1 даёт явное согласие на навигацию только этой вкладки; параметры сохраняются, служебный marker удаляется. Нет unregister-all, очистки caches/localStorage или затрагивания чужих scopes.
- Навигацию client.navigate нельзя ожидать внутри activate waitUntil: navigation сама ждёт завершения activate и возникает deadlock. Реальный тест обнаружил это; обработчик инициирует навигацию, завершая activate без ожидания её результата.
- test:update воспроизводит настоящий исторический commit552750e, а не синтетический экран. Временный export использует текущие установленные node_modules; зависимости и исходники основного checkout не меняет. CI checkout получает историю для fixture. Проверяются оба порядка миграции, сохранение demo/config, соседняя вкладка, следующий prompt с открытым черновиком и offline. Fresh live smoke остаётся отдельной post-deploy проверкой.
