# Техническое задание (ТЗ), Архитектура и Пайплайн разработки: Аналитическая панель департамента для Meta Quest 3S

## 1. Суть проекта и логика работы системы

### 1.1. Назначение системы
Система представляет собой клиентское пространственное веб-приложение (**WebXR / PWA** с возможностью сборки в `.apk`) для шлема **Meta Quest 3S**. Приложение получает аналитические показатели департамента через **REST API** (или из встроенного локального хранилища мок-данных) и отрисовывает **10 операционных дашбордов (разделенных на 3 тематических блока)** в трехмерном пространстве перед руководителем.

### 1.2. Архитектура потока данных (Моки ↔ Админка ↔ Боевой API)
Чтобы разработка, тестирование и демонстрация руководителю не блокировались готовностью бэкенда, заложена трехконтурная схема работы с данными:
1. **Автономный контур (Mock Data по умолчанию):** В проект встроен эталонный JSON-файл (`public/mock/dashboard-data.json`), содержащий полные данные для всех 10 дашбордов. Приложение запускается и работает из коробки без доступа к внутренней корпоративной сети.
2. **Панель администратора (`/admin` или модальное окно настроек):** Веб-интерфейс, открываемый с ноутбука разработчика или в плоском 2D-режиме браузера. Позволяет без изменения кода и пересборки проекта:
   - Ввести `Endpoint URL` боевого REST API и `Authorization Bearer Token` (что исключает необходимость набирать длинные URL и токены на виртуальной клавиатуре внутри VR-шлема).
   - Протестировать соединение кнопкой **«Ping & Validate Schema»** (проверка HTTP-статуса, времени отклика в миллисекундах и наличия обязательных секций `block1_payments`, `block2_cashDesk`, `block3_atmTso`).
   - Задать интервал автоматического обновления данных (`Polling Interval`: 5, 15, 30, 60 секунд).
   - Изменять ключевые показатели вручную в реальном времени или переключать готовые тестовые пресеты (штатный режим, сбой оборудования / простой АТМ, закрытие года) — изменения мгновенно синхронизируются с открытой VR-сценой через `localStorage` и `BroadcastChannel`.
3. **Защитный фоллбэк (Graceful Fallback):** В режиме `Hybrid (Live API + Fallback)` приложение запрашивает данные с боевого сервера. Если сервер не ответил за 4 секунды, вернул ошибку `500`, заблокирован по `CORS` или прислал невалидный JSON, приложение не выводит экран ошибки перед руководителем, а бесшовно отображает последний валидный слепок данных (или мок-данные), помечая статус компактным индикатором `FALLBACK MOCK`.

### 1.3. Пространственная организация и адаптация под оптику Meta Quest 3S
1. **Размещение в пространстве (3 панели по дуге вместо плоских вкладок):**
   Пользователь находится в центре координат `(0, 1.6 м, 0)`. На расстоянии `1.8 м` от глаз полукругом расположены 3 панели:
   - **Центральная панель (`0°` прямо перед глазами) — Блок 1 «Платежи» (Дашборды 1, 2, 3, 4):** главные показатели количества, объема платежей, доли в ДБО и выполнения годового плана.
   - **Левая панель (`+28°` поворот головы влево) — Блок 2 «Кассовые операции» (Дашборды 5, 6, 7):** типы кассовых операций, выполнение годового плана касс, график работающих касс по дням, количество открытых вакансий кассиров и процент простоя касс.
   - **Правая панель (`-28°` поворот головы вправо) — Блок 3 «Оборудование ATM / ТСО / Recycle» (Дашборды 8, 9, 10):** количество и объем операций в устройствах самообслуживания за месяц и с начала года, динамика работающего оборудования по дням и процент простоя по каждому типу устройств.
2. **Взаимодействие (Hand Tracking + Контроллеры):**
   - Поддерживается управление как стандартными контроллерами Meta Quest Touch Plus (лазерная указка + курок), так и **голыми руками без контроллеров (Hand Tracking 2.0)** — наведение взгляда/луча ладони и смыкание большого и указательного пальцев (жест `Pinch`).
   - **Функция `Deep Focus` (приближение дашборда):** клик или жест `Pinch` по любому из 10 дашбордов плавно выдвигает выбранную карточку в центр перед глазами на расстояние `1.1 м` в увеличенном масштабе для детального чтения цифр. Повторный клик возвращает карточку на место.
   - **Два режима окружения:** режим **Passthrough MR** (панели висят в реальном кабинете руководителя поверх видеопотока с цветных камер Quest 3S) и режим **Immersive Dark** (затемненное виртуальное окружение для полной концентрации на графиках).
3. **Учет физических особенностей линз Френеля в Meta Quest 3S:**
   В отличие от старшей модели Quest 3, в **Meta Quest 3S** используются **линзы Френеля** с разрешением `1832×1920` на глаз и выраженным пятном максимальной резкости в центре (`sweet spot`). Поэтому в ТЗ зафиксированы жесткие оптические правила:
   - Никакого мелкого текста: минимальный размер подписей эквивалентен `18–20px`, заголовков — `24–28px`, ключевых цифр KPI — `40–64px` (шрифт `Inter` Medium/Bold/ExtraBold с табличными цифрами `tabular-nums`).
   - Отказ от чисто белого текста `#FFFFFF` на чисто черном фоне `#000000` (в линзах Френеля это дает паразитные ореолы и лучи `God rays`). Используется мягкий светло-серый текст `#F8FAFC` на темно-графитовой полупрозрачной подложке `rgba(20, 25, 38, 0.78)` со скруглением углов `24px` и тонкой контурной рамкой `1px solid rgba(255, 255, 255, 0.18)`.
   - Для 100% поддержки кириллицы (русский и украинский языки) рендеринг карточек выполняется через High-DPI HTML/Canvas-слои в 3D-пространстве (`<Html transform>` из `@react-three/drei` + `Apache ECharts` + `troika-three-text`), что исключает проблему пустых квадратов `□□□` вместо кириллицы в стандартных MSDF-шрифтах.

### Важное правило цветовой индикации спидометров (Бизнес-логика)
В системе используются **два разных типа спидометров**, которые ни в коем случае нельзя красить по одной и той же формуле:
1. **Спидометры выполнения плана (Д4, Д5, Д6, Д8, Д9):** на макете ПМ срез сделан в начале года (февраль), поэтому годовой план выполнен на `5,2% – 8,3%`. Это **нормальный темп начала года**, поэтому дуга спидометра окрашивается в позитивный лаймово-зеленый цвет (`#84CC16` / `#34D399`), а не в аварийный красный.
2. **Спидометры простоя (Д7 «Простой касс» и Д10 «Простой оборудования ТСО/АТМ/Rec»):** здесь работает **обратная (инвертированная) шкала** — чем ниже процент простоя, тем лучше:
   - `0% – 2,0%` — изумрудно-зеленый (отлично);
   - `2,1% – 6,5%` — лаймово-желтый (допустимый рабочий уровень);
   - `> 6,5%` — тревожный красно-коралловый (`#F87171`, сигнализирует об аварии сети).

## 4. Программы и утилиты для установки (Разработка и Тестирование)

### 4.1. На компьютер разработчика (для работы без физического шлема)
1. **Браузер Google Chrome / Brave + расширение [Immersive Web Emulator](https://github.com/meta-quest/immersive-web-emulator)** — открывается через `F12 (DevTools) → вкладка WebXR`. Позволяет выбрать профиль `Meta Quest 3`, включить режим `AR Passthrough` и вращать виртуальный шлем и руки мышкой.
2. **[Meta XR Simulator](https://developers.meta.com/vr/downloads/package/meta-xr-simulator/)** — десктопный симулятор среды Horizon OS с готовыми [3D-комнатами для проверки MR-панелей](https://developers.meta.com/vr/documentation/unity/xrsim-heroscenes/).
3. **[Meta Quest Developer Hub (MQDH)](https://developers.meta.com/vr/documentation/unity/ts-mqdh-getting-started/)** ([Windows](https://developers.meta.com/vr/downloads/package/oculus-developer-hub-win/) / [Mac](https://developers.meta.com/vr/downloads/package/oculus-developer-hub-mac/)) — официальная утилита для подключения шлема, установки `.apk` файлов, просмотра логов и записи видео с экрана очков.
4. **Node.js (v20+ LTS) + Git + редактор с ИИ-агентом** (Cursor / VS Code + Cline / Claude Code).

### 4.2. На шлем руководителя Meta Quest 3S
- **Основной способ (за 30 секунд без проводов — PWA):** В шлеме открывается штатный **Meta Quest Browser**, вводится HTTPS-адрес развернутого дашборда и нажимается иконка «Установить приложение (Install PWA)» в адресной строке. Иконка аналитики появляется в главном меню очков.
- **Альтернативный способ (через `.apk` файл):** В мобильном приложении **Meta Horizon** на смартфоне включается `Режим разработчика (Developer Mode)`, после чего собранный `.apk` загружается на очки через [Meta Quest Developer Hub](https://developers.meta.com/vr/documentation/unity/ts-mqdh-getting-started/).
