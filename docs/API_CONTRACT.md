# Контракт данных

Версия реализации 0.1.0. Канонический образец: `public/mock/dashboard-data.json`. Исполняемая схема: `src/api/schema.ts`. Адаптер отображения: `src/api/model.ts`. Исходное описание: SPEC §6.

## Транспорт и валидация

`GET <configured endpoint>`, `Accept: application/json`, опциональный `Authorization: Bearer …`. Таймаут 4000мс, cookies не отправляются, redirects не принимаются (защита от неожиданной пересылки токена). Non-2xx, неверный JSON, неверная схема или сетевой сбой считаются ошибкой. Тело ограничено 1 МБ после чтения и по Content-Length, если заголовок предоставлен. Боевой сервер должен сам ограничивать ответы; клиент не является транспортным rate limiter.

Проверяется всё дерево десяти дашбордов, а не только наличие блоков. Все числовые значения конечные и неотрицательные, не выше Number.MAX_SAFE_INTEGER. Доля ДБО и простой — 0..100; выполнение плана допускает 0..1000 для перевыполнения. Вакансии целые. Массивы временных рядов ограничены 366 точками; линии Д10 и массив days одинаковой длины. Пустые графические ряды допустимы и отображаются как «Нет данных». Структурные наборы имеют фиксированную длину (3 KPI/плана/YTD; 2 gauge устройств; 3 типа простоя).

Незнакомые поля удаляются валидатором. Подписи 1..120 символов, валюта 1..8, delta до 24, цвета секторов — только шестизначный HEX. JSON не вставляется в HTML, подписи отрисовываются текстом.

## Верхний уровень

| Path | Type | Meaning |
|---|---|---|
| meta.reportDate | string | Отчётный месяц, отображается как получен |

## Объекты дашбордов

- `block1_payments.dashboard1_channels`: `channels: {name,jan,cur}[]` (до 20; значения в **млн шт.**), `dboSharePercent`.
- `dashboard2_monthlyCount`, `dashboard3_monthlyVolume`: `planBars: {label,percent}[3]`, `cards: {title,value,delta,spark:number[]}[3]`. Д2 value в шт., Д3 value в валюте meta.currency. Delta — строка источника; она не пересчитывается из неполного временного ряда.
- `dashboard4_ytdMain`: `{label,percent,value,scaleMode:'ytd'}[3]`. Индексы: количество / объём / прибыль. Последние два — денежные.
- `block2_cashDesk.dashboard5_operationTypes`: `monthlyPlanPercent`, `types:{name,count,color}[]` (до 12). Count в шт.; цвет из проверенного HEX.
- `dashboard6_ytdMain`: три YTD gauge — количество / объём / прибыль.
- `dashboard7_operationsAndStaff`: `workingCashDesksByDay:number[]`, `staffShortageVacancies:number`, `downtimeTodayPercent:number`. Исходный контракт не задаёт даты кассового ряда; подписываются последовательные дни 01..N, эта договорённость должна быть подтверждена для live API.
- `block3_atmTso.dashboard8_operationsCount`: два YTD-формата gauge, месячное количество / с начала года; labels определяют период, scaleMode исторически называется ytd даже для месячных.
- `dashboard9_operationsVolume`: аналогично Д8, value в валюте.
- `dashboard10_workingEquipmentAndDowntime`: `days:string[]`, `tsoLine:number[]`, `atmLine:number[]`, `recLine:number[]`; `downtime:{name,percent}[3]`.

## Семантика графиков

План и простой имеют разные шкалы цвета. План — зелёная дуга, точный percent; это не утверждение соответствия календарному темпу. Простой: <=2 зелёный; >2 и <=6,5 предупреждение; >6,5 тревога. Красный текст вакансий при >20 из исходного ТЗ. Перевыполнение подписывается точным процентом, полукруг визуально ограничен 100%; малые значения не растягиваются. Количество и денежные объёмы не смешиваются, сумма Д1 не подменяет Д2.

## Обновление и хранение

`mock`: локальный срез; `simulation`: изменяемый пользователем mock; `live`: валидный API; `fallback`: последний live либо mock; `error`: Strict Live недоступен. UI показывает, какой снимок используется. Последний live хранится только в памяти, сохраняется при очередном сетевом сбое, очищается при сохранении нового подключения. Время успешной загрузки не обновляется при fallback.

Смена конфигурации/применение demo отменяет запрос и увеличивает поколение: старый ответ не может затереть новые данные. Polling выполняется последовательно. Настройки без токена и demo JSON могут сохраняться в localStorage. `vr_analytics_channel` и storage events переносят только демоданные. Live-снимки и секреты не транслируются.
